# M1 — Time and profiles

**Goal:** turn real and synthetic load and PV data into kW series on any time grid, exactly, with
nothing passing silently. Design: SPEC §3 (time), §6 (profiles), decisions 7–12.

## Tasks

1. **Time** (`domain`)
   - [x] `TimeGrid`: half-open UTC range, step dividing 60 min, timezone for wall-clock logic; index
         ↔ timestamp, slicing, `with_step()`; typed errors for misaligned or empty grids.
   - [x] `Quantity` and `TimeSeries`: read-only array on a grid; compatible arithmetic only;
         `energy()` from power.
   - [x] Overlap-weighted resampling between any two steps: means for power/price/shape, sums and
         proportional splits for energy.
2. **Profiles** (`domain` + `ports`)
   - [x] `ProfileMeta`, `ProfileRef` (with `time_shift`), `ProfileSource` port (`catalog`, `shape`).
   - [x] Scaling: `Nominal(annual_kwh)`, `Calibrated(energy_kwh, window)`,
         `PVSystem(peak_kwp, specific_yield)`; the `Shaped(shape_ref, scaling)` profile spec; PV
         APIs will add a computed spec behind the same resolver (no placeholder code meanwhile).
   - [x] Coverage errors: a grid or calibration window outside the data fails, naming both periods.
3. **Adapters**
   - [x] Enedis parquet source (pyarrow; `ENEDIS_DB_PATH`; column configurable, default
         `coefficient_ajuste`; `timestamp_label = "start"`; mixed 30/15-min resolution).
   - [x] CSV source: strict schema (offset-aware timestamps, declared quantity and unit, regular
         step, no gaps, size limit); security tests.
   - [x] Synthetic source: seeded household and clear-sky PV shapes, constants.
4. **Wiring**
   - [ ] `Settings` (pydantic-settings), registries of profile sources (entry points), the first
         dishka container in `bootstrap.py`.
   - [x] Contract test suite for `ProfileSource`, run against every adapter and a test-only plugin
         (PRT-1, PRT-2, MEO-PLG-4); file sources join it in task 3.
5. **Documentation**
   - [x] Notebooks `01-time-grid`, `02-time-series-and-resampling`, `03-load-and-pv-profiles`,
         on committed Enedis slices (≤ 1 MB, both resolutions) and the synthetic source.
   - [x] Script `scripts/export_profile.py`: profile, scaling, period, step → CSV.
   - [x] Architecture pages for time and profiles; ADR 0005 for the new dependencies.

## Acceptance criteria

- Resampling conserves energy and round-trips exactly (property tests); the 2026-03-29 and
  2026-10-25 daylight-saving days are covered.
- Golden: RES1 scaled to 3 500 kWh/year with `Calibrated` over 2024-10-01 + 12 months gives
  3 500 kWh over that window to 1e-9; `Nominal` gives the data's own year-to-year variation.
- Every adapter passes the `ProfileSource` contract suite; a test-only source passes it without
  editing existing modules.
- 100 % line and branch coverage; mutation score ≥ 90 % on the new code; docs build strict;
  notebooks run in CI.

## Findings

- The stored Enedis `PRD3_BASE` data holds solar values around midnight on 2024-10-05, at the
  resolution switch (probable 12-hour shift): shown and documented, not repaired.
- Enedis open-data API, for the future API source: the `/api/explore/v2.1/catalog/datasets/
  coefficients-des-profils/records` endpoint used by the user's fetcher works (checked
  2026-10-25), with a limit of about ten days of data per call, so requests must be paged by
  period. The dataset-metadata endpoint of the same compatibility layer answers HTTP 410.
